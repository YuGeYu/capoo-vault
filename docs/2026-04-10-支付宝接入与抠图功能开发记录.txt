1. 这次已经解决的问题，解决的方法，心得

已解决问题 1：rembg-web 已成功接入当前 Cloudflare Worker 项目
解决方法：
- 按 docs/rembg-web-接入方案.md 的方向，采用“浏览器端本地推理”而不是 Worker 端推理。
- 在前端 SPA 中新增了 /tools/remove-bg 路由。
- 新增 public/rembg-tool.js 作为独立工具逻辑模块。
- 模型文件放到 public/models/u2netp.onnx，并在 Worker 中为 /models/ 增加长缓存头。

心得：
- 当前项目本身是无构建前端，优先保持结构简单是对的。
- 抠图这种能力放在浏览器端执行，更适合当前项目，也更省后端资源。

已解决问题 2：rembg-web 运行时报“运行时未正确暴露：rembgWeb”
解决方法：
- 排查 UMD 包的实际全局对象名，确认它暴露的是 RembgWeb，而不是 rembgWeb。
- 在前端工具代码中兼容 RembgWeb 和 rembgWeb 两种名字，并统一做别名处理。

心得：
- 第三方库接入时，不能只按直觉猜全局名，最好实际验证 UMD 暴露对象。
- 本地复现报错后，再去检查官方发布包，是定位这类问题最快的办法。

已解决问题 3：start-preview.bat 双击后只闪一个黑框，没有正常启动
解决方法：
- 发现问题来自 bat 文件中的中文提示在 Windows 批处理中出现编码干扰，导致命令被拆坏。
- 将 start-preview.bat 改为纯 ASCII 输出。
- 启动前自动执行本地 D1 迁移。
- 启动 wrangler dev 后自动打开测试地址。

心得：
- Windows bat 脚本尽量使用 ASCII，尤其是面向双击执行的场景。
- 本地预览脚本如果不自动准备数据库，用户看到的往往不是功能问题，而是环境问题。

已解决问题 4：本地预览时报 D1 表不存在
解决方法：
- 在 start-preview.bat 中加入 npm run db:migrate:local。
- 验证 /api/bootstrap 能正常返回 200。

心得：
- 对有 D1 依赖的项目，本地启动脚本最好顺带做初始化，减少重复排障。

已解决问题 5：AI 抠图结果下载按钮不够明显，页面有面向开发者的文案
解决方法：
- 重写 public/rembg-tool.js 中的结果区布局。
- 增加明显的大按钮“下载去背景结果 PNG”。
- 去掉“上游项目/技术来源”等不适合普通用户的文案。
- 调整 public/app.js 和 public/styles.css，使入口和工具页文案更偏用户视角。

心得：
- 用户页和开发页要分开表达。
- 工具页的核心路径必须非常清晰：上传、处理、预览、下载。


2. 这次还未解决的问题，已经尝试的方法，心得

未解决问题 1：支付宝会员付费接入尚未完成
已经尝试的方法：
- 评估了 Stripe，但考虑到开发者和用户都在中国大陆，已转向更适合大陆环境的支付方案。
- 与用户确认支付宝开放平台是当前优先方向。
- 已梳理支付宝开放平台接入所需的最小关键信息：AppID、应用公钥、支付宝公钥、支付产品、回调地址、商品与权益配置。

心得：
- 方向已经明确，剩下主要是把“支付能力”正式落成“会员权限系统”。
- 支付本身只是入口，真正要做稳的是会员状态、订单状态和每日额度控制。

未解决问题 2：支付宝支付产品是否已完成正式开通尚未最终确认
已经尝试的方法：
- 已建议优先确认是否已开通电脑网站支付。
- 已建议使用固定 notify_url 和 return_url 方案。

心得：
- 如果支付产品本身还没签约完成，代码先写好也无法正式跑通。
- 这类平台侧状态必须尽早确认，不然会在联调阶段卡住。

未解决问题 3：会员体系数据库和接口还未正式落表
已经尝试的方法：
- 已完成需求收敛，确定免费用户和会员用户的每日额度方案。
- 已初步明确要增加会员表、订单表、每日用量表。

心得：
- 会员系统应该按“最小可运行版本”先做：
- 先做单一会员档位、非自动续费月卡、每日次数限制。
- 高级功能先预留字段，不急着首版就上。

未解决问题 4：支付宝密钥安全流程还需要规范化
已经尝试的方法：
- 已提醒不能在聊天中继续传播应用私钥正文。
- 已建议对当前已暴露私钥进行轮换。

心得：
- 密钥安全优先级高于开发速度。
- 后续接入时应全部通过环境变量管理，不在代码和文档中落私钥正文。
