主题：首页修复、排序补充、公告更新开发记录

1. 这次已经解决的问题，解决的方法，心得

已解决问题 1：首页亮色模式下，工具入口卡片的“关闭”按钮完全看不到
解决方法：
- 先定位首页工具入口卡片模板，确认按钮使用的是 `home-notice-close`
- 再检查样式文件，发现该按钮的可见样式只写在 `.notice-board .home-notice-close` 下，而首页工具入口卡片实际容器是 `.tools-entry-card`
- 将同一套按钮样式扩展到 `.tools-entry-card .home-notice-close`，并同步补齐 hover 与 dark-mode 对应规则
心得：
- 这类“按钮还在，但像没了”的问题，很多时候不是事件逻辑坏了，而是样式作用域写窄了
- 首页不同卡片虽然视觉相近，但只要容器类名不同，就不能默认共用样式

已解决问题 2：首页排序方式新增“按修改时间排序”
解决方法：
- 后端 `getPublicFolders()` 返回值中补加 `updatedAt`
- 前端首页排序逻辑增加 `updated-asc` 与 `updated-desc` 两个分支
- 首页排序下拉框新增“修改时间（从早到晚）”“修改时间（从晚到早）”两个选项
- 中间按需求做过一次完整回退，随后又按最新要求重新加回，最后状态以“已加回并上线”为准
心得：
- 排序功能不能只改前端下拉框，否则只是“有选项没数据”
- 这种前后端联动的小改动，最稳的方式是先补字段，再接分支，最后再上 UI 选项
- 用户需求在短时间内多次回退和恢复时，要明确记录“最终线上状态”，不然很容易自己把自己绕进去

已解决问题 3：新增最新更新公告
解决方法：
- 先确认公告不是写死在前端，而是存储在 D1 的 `announcements` 表
- 查询线上已有公告顺序和字段结构后，直接向远程 D1 插入一条新的有效公告
- 公告内容包含：新增 CSTI / YSTI 工具、今天的首页修复内容，以及对搜索功能现状的说明
心得：
- 对这种内容运营类变更，直接写库比改模板更合适，也更符合当前项目结构
- PowerShell 下直接拼长 SQL 很容易被中文引号和特殊字符打断，改成 SQL 文件再执行更稳

已解决问题 4：多次重新部署并确认线上版本更新
解决方法：
- 每次改动后先执行 `node --check`
- 再执行 `npm run deploy`
- 本轮涉及的线上版本包括：
- `80a86956-53a7-4bef-90d2-6faad617bef9`
- `d3e0af39-b29e-416c-92e4-b1e9bc52562f`
- `312af839-22a2-418c-9609-f67fc55b2efd`
- `29ed8f69-d002-4796-a81e-0c41fdaceede`
心得：
- 这种首页高频微调项目，边改边发比积压一堆改动后再一次性发布更容易定位问题
- 版本号要跟着记录，不然后面追溯哪次部署对应哪次需求会很痛苦

2. 这次还未解决的问题，已经尝试的方法，心得

未解决问题 1：首页搜索功能仍未真正恢复可用
已经尝试的方法：
- 重新梳理首页搜索的状态流，检查 `searchDraft`、`searchQuery`、`onInput`、`onSearchSubmit` 与 `refreshHomeSearchResults()` 的衔接
- 尝试把搜索逻辑改成多字段匹配，覆盖分类名、说明、slug、上传者，并支持多个关键词同时命中
- 调整搜索空结果提示，让“无数据”和“无命中”在界面反馈上分开
- 在本地和线上逻辑之间反复核对后，按要求将这部分搜索修改完整回退
当前状态：
- 搜索功能最终保持在旧状态，没有交付一个真正稳定的新修复版本
- 用户侧的感知仍然是：这个入口在界面上存在，但不能作为可靠功能来使用
心得：
- 这次搜索问题不像单纯的前端事件失效，更像历史链路里已经混入了更深层的不稳定点
- 改前端过滤条件只能改变“怎么筛”，但如果前后端对数据、状态、渲染边界的理解并不一致，修一层很容易在另一层重新炸掉
- 有些问题不是“再试一次就能成”，而是已经到了需要停下来承认它暂时不值得继续硬抠的阶段

未解决问题 2：还没有做一次完整的真实浏览器回归验证
已经尝试的方法：
- 已多次执行 `node --check`
- 已多次重新部署并确认版本发布成功
- 已按用户逐条反馈进行定点修复
当前状态：
- 目前仍以“问题驱动式修复”为主
- 还没有对首页完整交互、公告展示、排序切换、工具入口卡片关闭恢复等路径做一轮系统性人工回归
心得：
- 语法检查能保证“代码能跑”，但不能保证“页面表现正常”
- 对这种曾经出现过乱码、模板损坏、交互反复回退的项目，最终还是要靠浏览器里一项一项点过去才算真正放心
