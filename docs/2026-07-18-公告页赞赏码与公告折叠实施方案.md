## 3. 推荐后的最终产品行为

### 3.1 赞赏码位置

在 `/site-info` 公告页中，将赞赏区放在“置顶说明”之后、“完整公告与站务”之前。这个位置足够显眼，也不会挤占公告页首屏标题和返回按钮。

版式采用一个独立的双栏内容区，不嵌套进其他卡片：

- 左侧：`赞赏站长` kicker、`支持网站继续维护` 标题、简短说明“赞赏完全自愿，感谢你对内容整理和网站维护的支持。”
- 右侧：完整赞赏码图片。
- 桌面端图片显示宽度建议 `min(300px, 32vw)`，固定 `aspect-ratio: 1`。
- 小于 `768px` 时改成单栏，图片居中，宽度 `min(100%, 320px)`；不得让图片或文字溢出。
- 图片使用 `loading="lazy"`、`decoding="async"`，`alt="站长唐风正气的赞赏码"`。
- 图片外层可用普通链接指向图片自身并在新标签打开，便于查看原图；链接必须带清晰的 `aria-label`，不要写额外冗长操作说明。
- 同时适配浅色/深色模式、键盘焦点和 `prefers-reduced-motion`。

### 3.2 公告默认折叠和逐批展开

公告区始终按 API 原顺序显示，不改变后台排序语义。

- 每次进入 `/site-info`，显示数量重置为 2。
- 初始只渲染 `entries.slice(0, 2)`。
- 点击“再看 2 条”后，上限依次变成 4、6、8、10；最后不足 2 条时显示剩余数量。
- 展开时保留当前滚动位置，不跳回页面顶部。
- 一旦显示数量大于 2，提供“收起公告”按钮。
- 点击“收起公告”后立即重置为 2 条，并将公告区标题平滑滚入可见区域；在 `prefers-reduced-motion` 下使用无动画滚动。
- 公告少于或等于 2 条时不显示任何展开/收起控件。
- 控件附近显示轻量状态文本，例如 `已显示 4 / 10 条`。
- 按钮使用原项目现有按钮视觉体系，具有 hover、active、disabled、`:focus-visible` 状态；触控高度至少 44px。
- 使用 `aria-expanded` 表示是否超过初始 2 条，公告列表可使用 `aria-live="polite"` 提示数量变化。
- 不用 CSS 把剩余公告仅视觉隐藏；应只把当前批次写入 DOM，以保持键盘和读屏顺序正确。

### 3.3 APP 宣传大幅减少

保留 APP 功能，但将宣传从 5 个重复位置压缩到 1 个低干扰入口：

删除：

1. `public/js/app-renderers-beta.js` 顶部导航中的 `APP` 链接。
2. `public/js/app-renderers.js` 的 `homeQuickEntries()` 中“安卓APP”快捷按钮。
3. `public/js/app-renderers.js` 的 `compactFooter()` 中“下载安卓 APP”按钮及其独占段落。
4. `public/js/app-renderers.js` 的 `fullFooter()` 侵权删除操作区中的“下载安卓 APP”按钮。

保留：

1. `public/js/app-renderers-beta.js` 首页最底部的一个普通文本链接 `安卓APP`，作为全站唯一低频可发现入口。
2. `/app` 独立下载页及页面内下载按钮、版本、大小、SHA256 和安装说明。
3. `src/worker.js` 中 `/app` SEO 固定页、sitemap 条目和安卓下载路由。
4. `android-app/`、发布脚本、R2 文件及元数据，均不删除。

这样既符合“大幅减少宣传”，又避免让现有 APP 完全失去站内入口。删除后用 `rg` 确认除首页底部单一入口和 `/app` 自身内容外，不再有重复 CTA。

### 4.4 `public/js/app-renderers.js`

在 `renderSiteInfoPage()` 中：

1. 计算：

   ```js
   const initialCount = 2;
   const visibleCount = Math.max(initialCount, Number(state.siteInfoVisibleAnnouncementCount) || initialCount);
   const visibleEntries = entries.slice(0, visibleCount);
   const remainingCount = Math.max(0, entries.length - visibleEntries.length);
   const nextBatchCount = Math.min(2, remainingCount);
   const expanded = visibleEntries.length > initialCount;
   ```

2. 在置顶说明和公告列表之间插入赞赏区。
3. 公告列表由 `entries.map(...)` 改为 `visibleEntries.map(...)`。
4. 公告列表后增加批次控件：
   - `remainingCount > 0` 时显示 `再看 ${nextBatchCount} 条`。
   - `expanded` 时显示 `收起公告`。
   - 显示 `已显示 ${visibleEntries.length} / ${entries.length} 条`。
5. 空公告状态保持原行为，不显示控件。
6. 按第 3.3 节删除 `homeQuickEntries()`、`compactFooter()`、`fullFooter()` 中多余 APP CTA。

## 7. 回归风险与处理

- **风险：路由进入后仍保留上次展开数量。** 必须在 `route()` 的 `/site-info` 分支显式重置为 2，而不只是初始化 state。
- **风险：收起后页面滚动位置落在已被删除的 DOM 下方。** 重渲染后将公告标题滚入可见区域。
- **风险：服务端先显示 8 条再闪为 2 条。** 同步修改 `renderSeoSiteInfo()` 的 slice，但保留 API 全量数据。
- **风险：二维码在深色模式被滤镜处理或缩得太小。** 图片保持原色和 1:1 比例，移动端最大 320px，桌面约 300px，不使用滤镜。
- **风险：APP 被彻底藏死。** 保留首页 beta 页脚唯一普通文本入口和 `/app` sitemap，不删除功能代码。
- **风险：误用 `wrangler.toml` 发布同名 Worker。** 所有生产命令只用现有 `npm run deploy` 或显式 `-c wrangler.production.toml`。
- **风险：覆盖当前依赖升级。** 不还原 `package.json`/`package-lock.json`；最终 dry-run 与部署要基于包含它们的完整工作树。
