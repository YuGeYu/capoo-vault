## 4. UI/UX 方向

UI/UX Pro Max 的检索结果适合采用“内容优先、强封面、稳定卡片尺寸、明确焦点、响应式渐进披露”的方向，但不要照搬其紫色单色建议。本项目已经有粉色品牌色、青绿色状态色、白/深色语义变量，应延续现有视觉资产。

统一要求：

- 大厅和详情页保持同一套卡片、圆角、阴影、间距和交互反馈。
- 主要内容优先，减少纯装饰占高；1280x720 首屏应看到完整精选卡，并露出下方推荐网格标题或第一行内容。
- 卡片固定封面比例，图片加载前后不得引发布局跳动。
- 不使用横向轮播隐藏内容，不增加自动播放，不使用负字距，不增加装饰性渐变球。
- 按钮/图标控件最小触控尺寸 44x44px；陌生图标保留 `title` 或可访问名称。
- 卡片圆角不超过项目现有 `--card-radius`，不把卡片嵌套进卡片。
- 保持浅色/深色模式，正文对比度至少 4.5:1，键盘焦点清楚。
- 所有动画控制在 150-250ms，并服从 `prefers-reduced-motion`。
- 必测 1440x900、1280x720、768x1024、390x844、375x667。

## 5. 推荐频道内部算法

### 5.1 对用户呈现

推荐频道只显示：

- 一张“精选推荐”大卡。
- 一个统一标题“为你精选”。
- 一组已经打乱顺序的作品卡片。

不得在 UI 文案、标签、卡片角标、提示或空状态中解释下面的内部选取规则。作品卡只能保留内容类型、资源数、浏览量、发布者等原有公开信息。

现有“最新”“热门”独立频道继续保留，它们是用户主动选择的明确浏览模式，不属于推荐页规则泄露。

### 5.2 精选大卡

从全量公开作品中选择“比较新且热度高”的一个：

1. 按 `publishedAt` 降序取前 `min(20, 全量数)` 个作品作为近期候选。
2. 排除没有 `slug` 的异常项；优先选择有 `coverUrl` 且 `count > 0` 的项。
3. 在候选中按 `viewCount` 降序，发布时间降序，中文名称升序做稳定 tie-break。
4. 第一项作为精选大卡。
5. 精选大卡不得再次出现在下方混合网格。

这个规则在当前线上数据下会从近期作品里挑出热度较高者，而不是机械选最新一条。不要在页面展示“前 20 条”“热度最高”等规则。

### 5.3 混合候选池

默认目标数量 24，按以下顺序取数并去重：

1. **近期池 8 条**：剩余作品按 `publishedAt DESC` 取 8。
2. **高热池 8 条**：从尚未入选的作品按 `viewCount DESC` 取 8。
3. **待发现池 8 条**：从尚未入选的作品按 `viewCount ASC`、`publishedAt DESC` 取 8。
4. 若数据不足 24 条，从所有尚未入选作品中按稳定散列顺序补齐。

关键要求：

- 每次加入前用 `id || slug` 去重。
- 不设置固定浏览阈值，只使用全站相对高低排序。
- 不要把资源数 `count` 当成热度。
- 不请求详情 API 获取点赞/评论，避免首页产生 24 次以上额外请求。
- 不使用 `Math.random()`，否则每次渲染、搜索输入或主题切换都会跳位。

### 5.4 每日稳定打乱

将三类合并后再打乱，用户不能从卡片顺序推断选取规则。

推荐实现纯函数：

```js
function stableHash(value) {
  let hash = 2166136261;
  for (const char of String(value || '')) {
    hash ^= char.charCodeAt(0);
    hash = Math.imul(hash, 16777619);
  }
  return hash >>> 0;
}

function stableDailyShuffle(items, seed) {
  return [...items].sort((a, b) => {
    const keyA = a.id || a.slug || a.name;
    const keyB = b.id || b.slug || b.name;
    return stableHash(`${seed}:${keyA}`) - stableHash(`${seed}:${keyB}`)
      || String(keyA).localeCompare(String(keyB), 'zh-CN');
  });
}
```

使用现有 `todayKey()` 生成日期种子，例如 `${todayKey()}:lobby-recommend-v1`。同一天同一批数据顺序稳定，跨天自然更新。

不要把池来源写进 `data-*` 属性、HTML 注释或浏览器可见调试文案。验证时由执行AI在本地根据 `/api/bootstrap` 独立计算集合并与 DOM 链接核对。

### 5.5 搜索和其他频道

- 仅在 `currentChannel === 'recommend' && !state.searchQuery` 时启用上述混合算法。
- 推荐频道有搜索词时：隐藏精选大卡，以现有搜索结果顺序显示匹配作品，标题使用“搜索结果”，避免推荐算法吞掉匹配项。
- 最新频道：保持按 `publishedAt DESC`，显示最多 24 条。
- 热门频道：保持按 `viewCount DESC`，显示最多 24 条。
- 工具频道：保持 `HOME_RECOMMEND_TOOLS` 全部工具，不减少入口。
- 切换频道、清空搜索、主题切换后不得产生重复卡片或空白卡片。

## 14. 回归风险

- **推荐卡重复**：三类取数和精选排除必须共用同一个 identity Set。
- **推荐顺序不断跳动**：禁止 `Math.random()`；使用日期加作品 identity 的稳定散列。
- **泄露内部规则**：不输出池标签、data 属性、HTML 注释或面向用户的算法解释。
- **搜索结果被推荐逻辑截断**：搜索分支必须优先于无搜索推荐分支。
- **热度口径泄露**：只使用 bootstrap 已公开的 `viewCount`，不增加 `realViewCount`。
- **移动端功能被“精简”掉**：站长推、分享方式、排序、资源工具、评论和底栏必须逐项验收。
- **分享面板被底栏遮挡**：移动端 bottom sheet 的 `bottom` 要包含底栏高度和 safe-area。
- **图片网格 CLS**：媒体容器先固定 aspect-ratio，再加载图片/视频。
- **长中文或英文文件名撑开卡片**：使用 `overflow-wrap:anywhere`、两行截断和稳定卡片高度。
- **覆盖上一轮公告改动**：在当前 dirty tree 上增量修改，绝不回退公告页、图片和 APP 精简代码。
- **错误生产配置**：部署只使用 `npm run deploy` 或显式 `-c wrangler.production.toml`。
- **GitHub 与线上不一致**：先提交推送，再部署同一工作树；线上修复必须追加提交推送。
