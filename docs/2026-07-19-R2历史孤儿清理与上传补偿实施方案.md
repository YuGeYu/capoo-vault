## 1. 执行边界

本方案只处理 R2 未引用对象审计、经确认后的历史孤儿删除、上传失败补偿、导入失败清理和只读监控。执行 AI 必须保留当前工作区已有改动，不得使用 `git reset --hard`、`git checkout --` 或覆盖用户文件。

本轮方案制定不修改业务代码、schema、配置、D1、R2，不执行 `wrangler deploy`、删除对象或线上写操作。实际执行 AI 负责按下文实施、测试、提交、推送和部署；涉及 652 个对象的删除必须先生成清单并取得站长明确确认。

当前基线（以执行前重新核验结果为准）：

- 分支 `main`，基线提交 `0c73dae feat: add scheduled D1 session maintenance`，与 `origin/main` 同步。
- R2 bucket：`mmc-r2`，对象 5,879 个，总大小 `2,511,683,183` bytes。
- D1 `assets.r2_key`：5,224 个，全部能在 R2 找到。
- 未被 D1 引用对象 655 个；其中 652 个 `published/` 对象共 `327,009,547` bytes，另有 3 个 Android 固定下载对象必须保留。
- `pending/` 不能按前缀清理：其中 1,807 个对象对应 D1 的已发布资产。

执行前必须再次保存：`git status --short`、当前 commit、生产配置文件 hash、D1/R2 只读统计和 Cloudflare 账户/项目确认。若基线与本节不一致，暂停删除，重新生成 manifest。

## 2. 历史孤儿的唯一判定

不得按 `published/` 前缀全删。某对象只有同时满足以下条件才进入删除候选：

1. `key` 不存在于生产 D1 `assets.r2_key`；
2. `key` 以 `published/` 开头，且不在 `downloads/android/`、固定下载路由或其他保护清单；
3. `uploaded/last_modified` 早于执行时刻 30 天；
4. 能找到仍被 D1 引用的对象，且规范化 `ETag` 和 `size` 完全相同；
5. R2 元数据、D1 引用快照和重复来源都能写入 manifest，缺任一证据则保留；
6. 删除前复查仍未被 D1 引用、仍满足前缀/年龄/重复证据条件。

当前预期结果是 652 个、327,009,547 bytes；这只是验收参照，不是删除授权。`downloads/android/latest.apk`、`downloads/android/latest.json` 和版本化 APK 加入 protected 清单，无论是否被 D1 引用都不得删除。

## 3. 审计清单（manifest）

新增脚本 `scripts/audit-r2-orphans.mjs`，通过受保护的只读 inventory API 分页读取 R2，再读取 D1 全量 `assets.r2_key`。R2 `list({ limit: 1000, cursor })` 必须循环到 `truncated=false`；不要依赖单页结果。

建议新增受 `requireImportToken()` 保护的内部接口（只读、不可由公开前端调用）：

- `GET /api/admin/import/r2-inventory?cursor=...&limit=...`
- 将 `MMC_MEDIA.list()` 的 key、size、etag、uploaded、httpMetadata、cursor 原样返回；limit 强制为 1～1000。

脚本输出目录：`artifacts/YYYY-MM-DD-r2-orphans/`，至少包含：

- `r2-orphans.json`：完整候选、保护对象、未满足条件的统计和生成时间；
- `r2-orphans.csv`：便于人工逐行审阅；
- `r2-inventory.jsonl`：原始分页快照（必要时压缩，但必须可恢复）；
- `manifest.sha256`：JSON/CSV/快照及 manifest 本身的 SHA-256；
- `audit-summary.json`：对象总数、总字节、D1 引用数、候选数/字节、protected 数/字节、错误数。

每个候选至少记录：

```json
{
  "key": "published/<folder>/<asset>.<ext>",
  "size": 12345,
  "etag": "normalized-etag",
  "uploaded": "2026-03-21T...Z",
  "duplicateOf": "published/<folder>/<asset>.<ext>",
  "duplicateEvidence": { "etag": "...", "size": 12345, "d1Referenced": true },
  "reason": ["not_referenced", "published_prefix", "older_than_30d", "etag_size_duplicate"],
  "auditRunId": "..."
}
```

`ETag` 比较要去掉稳定的外层引号并按大小写不敏感比较；不能把仅同名、同路径或近似大小当作重复证据。候选 manifest 生成后，执行 AI 必须把候选数量、总字节数、protected 数量和 `manifest.sha256` 报给站长，停在确认门，未获明确确认不得 `--apply`。

## 4. 安全删除与回滚

新增 `scripts/delete-r2-orphans.mjs`，默认只读预演；只有同时传入 `--manifest <path> --apply --confirm <manifest-sha256>` 才允许删除。脚本要求：

- 读取 manifest 后逐项重新查询 D1 `assets.r2_key`；已重新引用、前缀不安全、年龄不满足、重复来源不再存在或 ETag/size 复查失败的项标记 `stale` 并跳过；
- 删除操作小并发（建议 3），每项写入 `deletion-journal.jsonl`，记录时间、key、结果、错误和 manifest hash；支持按 journal 续跑，不重复删除成功项；
- 优先调用受保护的内部 DELETE API，服务端再次执行 D1 引用检查；不允许脚本直接获得可任意删除 bucket 的长期凭据；
- API 仅接受 `published/` 安全 key，拒绝 `..`、反斜杠、空 key、`downloads/android/` 和其它非允许前缀；D1 已引用则返回冲突并不删；
- 允许 R2 强一致删除后，重新分页 inventory，与 D1 做全量比对。

删除后验收必须证明：候选成功删除数与 journal 一致；D1 引用对象仍全部存在；Android 3 个固定对象仍存在；没有新增非预期未引用对象；R2 总大小下降约 `327,009,547` bytes（以实际结果为准）。任何复核错误均视为失败，停止继续删除并保留 journal。

回滚不是从备份恢复二进制，而是使用 manifest 的 `duplicateOf`：仅当引用来源对象仍存在且 ETag/size 一致时，执行 AI 可将旧 key 复制回 R2，并在确认 D1 记录缺失时恢复对应资产记录。恢复前必须暂停公开访问受影响内容、备份相关 D1 行并单独记录审批；若 duplicateOf 已被删除或证据不完整，禁止猜测恢复。

## 5. 正常上传的 R2/D1 补偿

修改 `src/worker.js` 的 `writeUploadedAssets()` 时遵循现有并发上限 3：

1. 生成 records 后用 `Promise.allSettled` 完成当前上传批次，确保其它 PUT 已结束；
2. 只要任一 PUT 失败，收集成功上传的 key；先查询 D1 `assets` 是否已引用这些 key；
3. 仅删除确认未被引用的成功 key。引用复查失败时保守不删，记录结构化错误并交给孤儿审计；
4. 所有批次成功后再执行 D1 batch；D1 batch 抛错时同样重新查询引用后补偿删除，不能假设“响应失败”等于“事务未提交”；
5. 原始错误必须继续抛出，前端看到失败；补偿错误写日志但不能掩盖原始错误；
6. 将上传 key、D1 写入结果、补偿删除结果关联同一个 request/batch id，日志中不得输出用户内容或 token。

`createFolderWithAssets()` 先插入 folder，再写 assets。若后续失败，补偿流程须在确认该 folder 没有任何 assets、且仍由本次请求创建后删除空 folder；查询失败或发现已有资产时不得删除 folder，留给管理员审计。编辑/追加上传路径也必须复用同一补偿逻辑。

## 6. 旧站导入失败清理

同步处理 `scripts/import-legacy-site.mjs` 与 `scripts/import-legacy-site.ps1`，不能只修一个入口：

- 每批次维护 `attemptedKeys` 与 `uploadedKeys`，上传成功即持久化到批次 journal；
- 远端 `skipped`、slug 冲突、folder API 报错、网络中断或进程退出时，调用受保护 DELETE API 清理本批次已上传且未被 D1 引用的 key；
- 若 folder 提交响应超时，先重新查询 slug/folder/assets；确认已提交则不删；不确定时由服务端 D1 引用检查决定；
- 脚本退出码非 0 时保留 journal 和失败原因，支持重跑时跳过已成功提交批次；
- dry-run 不上传、不删除，只输出预计 key 和请求数量。

强化 `PUT /api/admin/import/upload`：只接受规范化的 `published/<folderId>/<assetId>.<ext>`，限制长度、扩展名和 content type，拒绝覆盖已有 key（除非明确的幂等 ETag 相同）。新增受保护 `DELETE /api/admin/import/r2-object`，服务端先查 D1 引用再删除。

## 7. 月度 R2 监控

新增 `schema/016_r2_storage_metrics.sql`，追加迁移而不重建数据库：

```sql
CREATE TABLE IF NOT EXISTS r2_monthly_metrics (
  month TEXT PRIMARY KEY,
  measured_at TEXT NOT NULL,
  object_count INTEGER NOT NULL,
  total_bytes INTEGER NOT NULL,
  referenced_count INTEGER NOT NULL,
  unreferenced_count INTEGER NOT NULL,
  unreferenced_bytes INTEGER NOT NULL,
  protected_unreferenced_count INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

在现有 `runDatabaseMaintenance()` 的每月分支中调用只读 R2 inventory 与 D1 引用比对，写入当月一行并输出 structured log；只监控和告警，不自动删除。固定 Android 对象计入 `protected_unreferenced_count`。R2 inventory 失败时不得写零值覆盖上次数据，应记录 `r2_metric_error`。

告警建议：单月总量增长超过 1 MB、未引用对象超过 1,000 个、未引用字节异常增长，或连续两月总量增长超过 20%。

## 8. 测试与故障注入

执行 AI 必须先在本地 mock R2/D1 跑测试，再部署：

- R2 分页 0/1/1000/1001/多页，重复 key、缺 etag、旧时间和未来时间；
- D1 引用命中、未命中、重复 ETag+size、同 size 不同 ETag；
- 保护 Android key、`pending/` 有效引用、路径穿越和非法前缀；
- 第一个/中间/最后一个 PUT 失败，验证 allSettled 等待完成且只删未引用成功项；
- D1 batch 实际提交后返回错误，验证引用复查阻止误删；
- 引用复查失败、DELETE 超时、进程中断，验证保守保留和 journal 续跑；
- import skipped、slug 冲突、folder 提交超时后重查成功，验证不会误删已提交媒体。

通过 `node --check`、项目既有测试和部署前构建检查；测试中不得连接生产 bucket 执行删除。

## 9. 生产发布与验收顺序

实际执行 AI 按以下顺序操作：

1. 重新核验工作区、生产 `wrangler.production.toml`、D1/R2 只读基线；
2. 实现 API、脚本、补偿逻辑和 `schema/016`，保留现有未相关改动；
3. 本地 mock/故障注入测试，执行迁移到测试或生产 D1 前先备份并记录迁移输出；
4. 先部署代码和迁移，验证上传、导入、inventory API 的鉴权、路径限制和只读行为；
5. 运行 `audit-r2-orphans.mjs` 生成 manifest，报告数量、字节数和 SHA-256，等待站长明确确认；
6. 仅在确认后运行 `delete-r2-orphans.mjs --manifest ... --apply --confirm ...`，实时保留 journal；
7. 运行删除后全量复核、固定下载路由检查、D1 引用完整性检查和月度指标检查；
8. `git diff`、测试输出、部署版本、线上 URL 和 manifest/journal 路径全部归档；提交并推送 GitHub。生产部署必须使用 `wrangler.production.toml`，不要误用默认配置。

建议的只读/部署命令模板（由执行 AI 按实际脚本参数调整）：

```powershell

node --check scripts/audit-r2-orphans.mjs
npm run deploy -- --config wrangler.production.toml
```

命令只作模板；若项目没有对应 npm script，执行 AI 必须先查 `package.json`，不得盲目执行。任何线上写操作均需在报告中列明时间、操作者、命令、结果和 Cloudflare deployment id。

## 10. 明确暂缓事项

- 不给 `pending/` 设置生命周期删除规则；如未来需要，新增 `staging/` 前缀并只对其设置 24～72 小时生命周期。
- 不在本次无产品确认地降低 50 MB 单文件限制或增加文件夹总容量限制；图片 WebP、GIF/视频转码列为后续产品决策。
- 不立即做内容哈希去重。现有 `assets.r2_key` 唯一约束和 1:1 删除逻辑，去重需要引用计数、迁移、最后引用删除和回滚设计。
- 不删除 Android 固定下载资源，不删除任何仅因前缀或“看起来旧”而未满足完整证据链的对象。
